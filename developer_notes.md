Developer notes and processes:

How the process went sequentially:

To start, started with the basic framework from lab 4 for main.py file, and main engine file, renamed it to pang.py

Decided to create an objects.py file to hold all my objects:

Differentiation of code: Interactions between objects will occur in pang.py and isolated logic for each object will happen in object.py along with their initializaion and animation

Timeline:
1.Already had player class, and ball class from the lab 4
2.Next slightly altered ball class via giving it fields that are necessary like points, and size, and isActive
3. Initialized all balls first as inactive except big balls
4. Next was to work on the shoots, so initalized those as well and they are just rectangles with fields like velocity position, isActive etc, when player actives a shoot becomes is active and position is put where the player is 
5. The next thing was making it so that the score is incrememnted and displayed as well as the individual ball score when a ball was shot. Used a "Display Point" class with fields like the number of frames itd be active for and any time a ball is shot the proper "display ppoint" is added to an array in the game which is rendered 
6. Next I worked on collsions mechanices, pretty simple, just iterate through for each active thing are there pertinient collsions between them, if so, toggle appropriate fields and whatnot
7. Once collision was handled, the next step was animation which may have been one of the most time consuming parts. First and foremost the appropriate sprite sheets were needed to match my theme, at first went for hazmat theme like nuclear radiation, but the sprite sheet for that was really hard to work with due to inconsistent dimensions and spacing which made my methods of animation infeasible.
8. Without going into every single animation method, they all pretty much follow the same pattern
9. Basically, object has a field called frame timer, and every frame this incremented, once this has been incremented a certain amount of times, the index of the frame from the sprite sheet is incremented (the field current frame). From the current frame the appropriate starting x is calculated for the frame rec, and that comes from The desired sprites width, the initial x offset, and the gap between characters: ex: self.frameRec.x = WALK_OFFSETX + (GAP_BETWEEN_WALKING_SPRITES * self.current_frame) + self.current_frame * CHARACTER_WIDTH_WALKING. TO GET these constants you need to go into preview and measure with your cursor which not gonna lie was a bit tedious
10. Animation calibration and measurement took a long time, and once this was done I noticed that sometimes the player would die to a ball even though it didnt look like they were touching it. 
11. This led me to give a new approach to PLAYER vs entity collisions, the player would have a smaller hitbox than their sprite to give leniency, this took a bit of trying different things and failing but at the end decided to just calculate and instantiate new collsion rectangle based on position. 
12. Noticed that the game was really hard especially as the balls kept getting lower as a game progresses so decided to give the player an invulnerability dodge so they could pass through balls. Now collisoin detected checks "is dodging" before penalizing player
